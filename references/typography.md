# 字体阶梯与可读性

> 用户说“字太小”，不是让你把某一个字号 +1。  
> 这是 **type scale 缺失**：不同层级的字没有稳定的最小值和比例。

## 1. RONGE 的最小字号

以 iPhone 390pt 宽度、普通视力和忙碌场景为基线：

| 层级 | 最小字号 | 行高 | 用途 |
|---|---:|---:|---|
| Display | 32–40 | 1.1–1.2 | 一屏唯一主角（结论、关键判断） |
| Title | 26–30 | 1.2 | 页面主标题 |
| Headline | 20–24 | 1.25 | 卡片标题/新结论 |
| Body | **15–17** | 1.4–1.5 | 正文、说明、选项描述 |
| Callout | 14–15 | 1.4 | 重点说明、次行动 |
| Subhead | 13–14 | 1.35 | 标签、辅助信息 |
| Footnote | **12–13** | 1.4 | 来源、时间、注释 |
| Caption | **11–12** | 1.35 | 只放装饰性/非关键元数据 |

**硬规则：**

- 影响判断、选择、行动的文字，**不得小于 15pt**；
- 用户需要读懂的说明、来源、标签，**不得小于 12pt**；
- 11pt 只允许装饰性元数据，不得承载原因/结论/操作；
- 8–10pt：**禁止**用于任何用户需要读的信息；
- 不要用“全大写 + 超宽字距 + 8pt”冒充高级感。

## 2. 一屏只允许 3–4 个层级

推荐：

```text
Display 36（新结论）
Body 15–17（原因/影响）
Subhead 13（上次/现在/来源标签）
Caption 12（时间、脚注）
```

如果出现 8/9/10/11/12/13 五档，说明层级失控。  
合并层级，而不是继续加字号。

## 3. 对比度与字重

- 正文 ≥ 4.5:1；
- 大字号 ≥ 3:1；
- 关键旧状态、来源、标签不能低于 3:1；
- 不要用 300 字重 + 浅灰色表达“高级”；
- 方向词（↑/↓、更稳/更难）必须同时存在，不能只靠颜色。

## 4. Dynamic Type

- 正文用可缩放单位，不写死到无法放大；
- 至少测试 extra-large / accessibility-large；
- 大字号下标题换行、按钮不被推走、底部不被遮挡；
- 截断时保留结论和主行动，舍弃装饰标签。

## 5. 截图字体审计

1. 100% 比例看截图，不缩放；
2. 手臂距离看 3 秒：能不能读到结论和下一步；
3. 灰度看：弱化的旧结论是否还能读；
4. 眯眼看：第一落点是否是结论，不是小标签；
5. 大字号再截一张，确认不破版。

**任何一张需要用户“凑近看”的截图，都不算交付。**

## 6. 常见错误

- 用 8–9pt 全大写小标签当“设计感”；
- 关键标签（上次/现在/来源）比正文小两档；
- 把 13 个字以上的行动文案塞进 11pt 按钮；
- 为了“留白”把正文压到 12–13pt；
- 用浅灰 + 细字重表达层级，结果看不清；
- 只改一个字号，不检查行高、对比度和层级。
