# 元素独立性

> 一个元素该不该单独拿出来，不是看它“放得下吗”，而是看它**离开父对象后还成不成立**。

## 1. 独立前四问

1. 去掉卡片/分组/上下文后，它还是一句完整的话或动作吗？
2. 用户知道它作用于谁吗？
3. 它的视觉重量独立后还撑得住吗，还是会变成孤零零的小字？
4. 它和主行动、父卡片的关系是否仍然清楚？

## 2. 判定

| 结果 | 处理 |
|---|---|
| 独立后仍然完整、可读、有分量 | 可以独立 |
| 是某个父对象的次级动作/说明 | 附着：footer、行内、卡底、同一分组 |
| 独立后只剩装饰或歧义 | 删除或合并 |
| 独立后比主行动更抢眼 | 降权，移回父对象 |

## 3. 当前案例

首页原来的 `稍后 / 不再提醒` 漂在玻璃卡外：

- 单独看，两个小字不知道在对谁说话；
- 主行动在卡内，退出动作在卡外，像两个没人管的标签；
- 视觉上出现“一张卡 + 两行孤儿文字”。

处理：

- 主行动改为卡内深色按钮；
- 退出动作移进同一张卡的 footer，用细线与主行动分开；
- 退出仍比主行动轻，但不再孤立。

## 4. 附着方式

- **卡底 footer**：适合退出/次级动作；
- **行内右侧**：适合状态、来源、时间；
- **同一分组**：适合一组互斥选项；
- **顶部工具条**：适合编辑/完成/取消；
- **不要**为了留白把有语义的动作单独漂在页面空白处。

## 5. 反模式

- 主行动在卡里，退出在卡外；
- 两个同权小字漂在页面底部；
- 一个标签离开它修饰的对象；
- 为了“空”把按钮和上下文拆开；
- 独立后需要用户猜“这是对谁说的”。

## 6. 审计

- [ ] 独立元素去掉父容器后仍成立吗？
- [ ] 主行动和退出动作是否在同一个物件里？
- [ ] 有没有漂在空白处的孤立小字/按钮？
- [ ] 独立后是否比主行动更抢眼？
- [ ] 附着关系是否只用一条线/一个 footer 就够，不需要再加容器？
