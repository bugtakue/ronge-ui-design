# 独立设计评论员

> 用法：每轮启动一个**全新上下文**的子代理；只给截图路径，不给代码、实现说明或旧评论。
> 同一轮所有方向使用同一份提示词，保证评分可比。

## 1. 校准（推荐）

在正式打分前，可选做一次“相对排名”校准：

1. 找 4 张同方向的专业案例截图（产品官网、Dribbble/Behance、真实商店截图）；
2. 加上 1 张候选截图；
3. 让评论员只按“打磨程度/品味”排名，不告诉它哪张是候选；
4. 候选排不进前 2，先别谈 9 分。

这比“你觉得好不好看”更客观。专业案例只用于内部校准，不打包进开源仓库。

## 2. 提示词模板

```text
你是独立的设计评论员，只看截图，不看代码、不看实现说明、不看之前的迭代。

请用 read_image 读取这些真实 iPhone 截图：
A: <path>
B: <path>
C: <path>

产品：<一句话产品定位>。
这一屏的唯一任务：<一句话>。
用户：<普通但忙碌的人 / 具体人群>。
用户偏好：<已知审美偏好>。

请按以下方式评审：

1. 第一眼：你注意到了什么？会不会想点？为什么？
2. 是否像 AI 生成 / 通用模板？指出具体模板家具，不要只说“有点 AI”。
3. 对每个方向，想象一家顶级设计工作室会如何执行这个美学方向；
   指出它离“工作室级”最大的 2–3 个差距。必须具体到：
   - 主角与视觉重量；
   - 信息层级和动作层级；
   - 因果/影响是否被看见；
   - 图与留白的关系；
   - 文案是否在翻译用户处境，还是在解释产品；
   - 手机可读性、安全区、tab bar、被切断的卡片。
4. 对每个方向按 0–10 打分：
   10 = 顶级工作室；7 = 可上线但普通；5 = 有明显问题。
   维度：记忆点、信息层级、点击欲望、克制、手机可读性。
5. 检查：
   - 无价值元素；
   - 假数据/假图表/假按钮；
   - 过度解释；
   - 同一件事是否讲了三遍；
   - 是否有来源、时间、角色。
6. 只给设计判断和视觉修改建议，不给代码建议。

最后只输出 JSON：
{"scores":{"A":x,"B":x,"C":x},"recommended":"A|B|C|none","top_gaps":["..."],"one_sentence":"..."}
```

## 3. 评分契约

- 每个方向独立打分，不互相抄；
- 只看截图，不推测交互实现；
- 不因为“看起来高级”给分，按记忆点/层级/点击欲/克制/可读性；
- 发现假数据/假图表/假按钮必须写进 `top_gaps`；
- 如果请两个评论员，报告分数区间，不取最高分；
- 人工用户品味高于评论员，最终确认权在用户。

## 4. 复评规则

| 分数 | 动作 |
|---:|---|
| 9–10 | 进交付；仍需用户确认 |
| 7–8.9 | 按 `top_gaps` 做结构性修改 |
| 5–6.9 | 有明显问题，回 Discover 重排 |
| <5 | 重做，不磨皮 |

- 每轮只让它看新截图，不给旧评论；
- 连续两轮 <7：重写 brief 或换方向；
- 分数 ≥9 后，再做一次人工用户确认；
- AI 评分不能替代用户品味。

## 5. 评分校准

| 分数 | 含义 |
|---:|---|
| 9–10 | 有作者性、有记忆点、层级干净，愿意主动点 |
| 7–8.9 | 方向成立，但有结构性差距；可上线但不惊艳 |
| 5–6.9 | 有明显问题：主角错位、动作太多、因果不可见 |
| <5 | 模板/AI slop；重做，不要磨皮 |
