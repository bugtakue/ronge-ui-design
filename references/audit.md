# RONGE 交付检查表

> 每个新页面/改版在给用户看之前逐项过。不能因为“构建成功”就跳过。

## 1. 主角

- [ ] 一屏只有一个最大字号的主角。
- [ ] 结论/影响比引子更重。
- [ ] 视觉峰值没有落在装饰图或大按钮上。
- [ ] 遮住项目名，仍能看出这是该产品的判断。

## 2. 信息层级

- [ ] 标题、引子、结论、解释没有说同一件事三遍。
- [ ] “新事实 → 实际影响 → 新结论”在同一根轴。
- [ ] 变量有来源/时间/角色。
- [ ] 先给影响，再给变量。
- [ ] 关键旧状态可读，不是 2:1 对比度的装饰文字。

## 3. 动作

- [ ] 只有一个主行动，标签明确（动词 + 结果）。
- [ ] 退出动作明显更轻。
- [ ] 没有假按钮。
- [ ] 可点区域有文字或明确 affordance，不靠猜箭头。
- [ ] 用户点之前知道会得到什么。

## 4. 图与留白

- [ ] 图绑定来源、情绪或地面，不是纯装饰。
- [ ] 图不抢结论。
- [ ] 图上下缘处理干净，不被 tab bar 硬切。
- [ ] 留白托住判断，不在顶部/底部堆死白。
- [ ] 首屏不以被切一半的工具卡收尾。

## 5. 手机工艺

- [ ] 390×844 基线；iPhone 安全区正确。
- [ ] 主按钮 ≥ 44pt；tab bar 不遮挡内容。
- [ ] 正文 15–17pt；说明/来源 ≥12pt；关键文字对比度足够。
- [ ] 影响判断/行动的文字 ≥15pt；8–10pt 没有承载信息。
- [ ] 一屏 3–4 个字号层级，不是 5 档以上。
- [ ] tab 图标/命名不互相拆台；不新增无用途控件。
- [ ] 没有 EN/四宫格/重复“整理”等模板家具。

## 6. 状态与无障碍

- [ ] 默认、安静/空、编辑、加载、错误、未登录都有设计。
- [ ] 长内容/大字号不破版。
- [ ] VoiceOver 标签、减少动态、颜色之外的方向词。
- [ ] 图片有 alt 或装饰标记。

## 7. 反 AI slop

- [ ] 没有卡片瀑布。
- [ ] 没有抽象节点图代替真实变量/影响。
- [ ] 没有假图表/空数据列。
- [ ] 没有“真正/本质/底层逻辑/维度/赋能/闭环”。
- [ ] 没有强行金句、古诗、宠物、无来源洞察。
- [ ] 不是“好看的 AI 简报”，而是“会替用户判断的助手”。

## 8. 交付

- [ ] 3 个方向都有真实 iPhone 截图（或用户明确只要 1 个）。
- [ ] 独立评论员只看截图评过分，记录分数。
- [ ] 删掉至少 3 个元素，并写明原因。
- [ ] 截图存到 `artifacts/`，路径写进 `docs/product-memory.md`。
- [ ] 明确写“未替换正式页面”，除非用户确认。

## 9. 开源检查（如准备公开）

- [ ] 已移走品牌名/logo/专属词/真实数据。
- [ ] 截图使用合成数据或已脱敏。
- [ ] 图片/字体/图标许可明确。
- [ ] 没有绝对路径、内网地址、token、App Store ID。
- [ ] 有 LICENSE、CHANGELOG、贡献指南。
